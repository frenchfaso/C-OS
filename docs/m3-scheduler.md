# M3 scheduler and bounded jobs

The normal target runs up to four statically linked processes autonomously.
`scheduler_tick` selects VM and native work in C64 code; the monitor starts a
paired PRG/REU image and collects coarse observations. It sends no opcode,
fuel, cache-service or syscall-completion commands during execution.

## Process turns and waits

The runnable queue has four entries and rejects duplicate insertion. A new
turn receives 128 retired-opcode credits. An ordinary opcode can retain the
same logical turn across video windows and native phases. Exhaustion, YIELD
and SLEEP(0) end that turn and append the process to the queue tail. The next
turn receives 128 credits. Syscalls consume one credit when accepted.

An immediate syscall, invalid request or EVENT_WAIT poll preserves remaining
credit. A positive sleep or actual event wait removes the process from the
runnable queue; its timed wake appends it at the tail with a fresh 128-credit
turn. REU waits and suspended memory jobs also leave the runnable queue, but
resume with their original remaining credit. Finishing one global REU
continuation can wake several memory-waiting owners without giving them new
credits. Cancellation also wakes them when revoking the requester or its
victim directly releases that driver; it does not rely on a later service
call to discover that release. Native call frames are completely unwound at every boundary.

The renderer increments an unsigned 32-bit frame counter once per PAL frame,
before its first synchronized pixel line. GET_FRAME takes an atomic snapshot.
Timed waits compare unsigned frame differences, including wrap from
`$FFFFFFFF` to zero. EVENT_WAIT timeout `$FFFF` remains indefinite. This stage
does not create windows or receive events: normal handles are zero and return
EBADF. Only the trusted native diagnostic harness installs synthetic owned
handles to test genuine timeout waits. Polls validate the complete 16-byte
writable record before returning EAGAIN; invalid records return the range or
code-protection error without receiving fuel.

## VM/native fairness and accounting

The scheduler remembers which of its two queues is owed the next phase. A
successful phase changes that owed turn. If the owed queue is unavailable,
the other queue can progress without consuming the owed turn. Video deferral
also preserves it. While a CPU memory job is pending, a VM phase attempts one
opcode; otherwise the interpreter can run to its next architectural boundary,
while admitting video before each opcode. This prevents a warm non-yield loop
from monopolizing the native queue.

One serialized REU continuation has priority until its bounded service phase
returns; it cannot be replaced by another request. Native scalar transfers
also retain explicit owner/generation continuations while coherency work is
incomplete. Successfully completed job phases rotate through the four owners.
Neither the owner cursor nor the owed-queue turn resets at a raster window.

Per-owner native PHI2 counters sample admitted requests, deferred coherency
attempts and cache service using CIA1 Timer A rather than host time. The
interval begins at the start snapshot and ends at the end snapshot; it
includes some timer setup/collection but excludes following accumulator,
cursor and phase-counter updates and context saving. Those costs remain in
the static full-phase bounds and elapsed GET_FRAME measurements. Per-owner
DMA-byte counters increment only when the
central driver reports an actual transaction. Each phase can perform at most
one transaction, so the byte serial at `REPORT+$1D` suffices to detect it.
Native job bytes count successful destination bytes; job chunks count both
read and write phases. A three-byte copy therefore takes twice as many
successful phases as a three-byte fill.

The idle horizontal-margin record uses the same future accounting convention,
but its default hook emits zero instructions. Qualification remains zero.
No useful work executes inside the active pixel interval. The normal M3
admission interval begins after pixel line 259 and ends at 299; the late guard
is 4410 PHI2 ticks. Extended/M2 profiles retain their separate admission rules.
Static conditional bounds are generated by `scripts/m2_bounds.py`; actual
target phase maxima are recorded separately. Functional emulation does not
qualify physical Ultimate interference or raster timing.

## Memory services and lifetime

MEM_FILL and MEM_COPY validate their complete 32-bit length before truncation.
Every nonempty source/destination byte must lie inside the owned arena;
destination code intersections return EBUSY. Address overflow, invalid ranges
and fill values above 255 fail before any job or transfer begins. A zero length
does not dereference either pointer. MEM_COPY chooses forward or backward
traversal after full validation and implements memmove overlap semantics.

Jobs transfer at most three bytes per CPU phase. Copies keep a private scalar
between their separate read and write phases. Every physical transfer uses
the common coherent cache driver: owned dirty source bytes are flushed before
reading, destination lines are invalidated before writing, and unrelated
owners remain coherent. Cross-line operands and REU waits use explicit
continuations rather than architectural stack frames.

Internal completion requires an active pending syscall, a nonzero job and
the same slot incarnation. Jobs and timers are synchronous kernel
continuations, with no detached external completion packet or callback. They
publish the status exactly once, remove the job and enqueue the owner.
Consumed descriptors and old-generation descriptors are inert after revoke.
External packets continue to use the M2 `vm_complete` 8-byte token and 2-byte generation
validation; the internal API does not accept arbitrary delayed status
callbacks against a later job in the same incarnation. EXIT and
fault remove runnable/job state but retain their context, arena and owned
dirty cache bytes for logical inspection. They do not make that arena free.
Trusted cancellation or replacement first revokes all native/cache/margin
continuations and removes queue entries. Replacement then increments the
incarnation, initializes a bounded owned arena seed, and publishes a fresh
validated 96-byte context. An old completion cannot affect it. This is a
trusted static-slot replacement boundary, not a PROC_RESTART service or a
general process loader.

Core implemented services are PROC_EXIT, SYS_INFO, GET_FRAME, SLEEP,
MEM_INFO, MEM_FILL and MEM_COPY. EVENT_WAIT implements validation and timed
waiting for the diagnostic handles described above. Other defined services
return ENOTSUP and unassigned IDs return ENOSYS; declared scalar outputs are
cleared consistently with the host service harness.

## Internal RAM and stack

`native/scheduler.inc` defines the internal layout. The four 128-byte PCBs at
`$0400..$05FF` retain the 96-byte M2 context and use their final 32 bytes for
process state, refill flag, job continuation, generation, timing and native
byte/phase counters. Globals occupy `$FE00..$FE7F`. Completion/replacement
staging aliases `$FE80..$FEDF` (at most 96 bytes). Scheduler scratch uses
`$80..$90`, reclaimed from bootstrap after the final runtime jump; steady
state never calls bootstrap DMA or timer helpers. All REU traffic uses the
cache driver's separate `$91..$AF` scratch.

The static hardware-stack bound for normal M3 is 18 bytes, or 30 including one
eight-byte renderer IRQ and one four-byte NMI. The deepest path is the kernel,
scheduler, VM run/step/dispatch and a prepared cache-byte lookup, including
two temporary pushed bytes. The bound assumes no recursive NMI or nested IRQ
and an unqualified margin hook. A startup-only `$A5` fill records the deepest
touched stack address without steady per-opcode instrumentation; its result
is an observed lower bound, not a replacement for the static proof.

## Reproduction

Build the Rust tools first, then pass explicit pinned assembler and backend
paths. For each cache line size 64 and 128:

```sh
python3 scripts/m3_ue2.py --native-contract --cache-line 128 \
  --kickass "$KICKASS_JAR" --java "$JAVA" \
  --emulator "$UE2EMU" --config "$UE2_CONFIG" \
  --flash "$UE2_FLASH" --settings "$UE2_SETTINGS" \
  --out build/m3-contract/128 --timeout 90
python3 scripts/m3_ue2.py --suite --cache-line 128 \
  --kickass "$KICKASS_JAR" --java "$JAVA" \
  --emulator "$UE2EMU" --config "$UE2_CONFIG" \
  --flash "$UE2_FLASH" --settings "$UE2_SETTINGS" \
  --out build/m3-autonomous/128 --milliseconds 24000 --timeout 90
```

The independent native harness executes 126 assertions with the real
interpreter/cache/job modules. It checks error atomicity, fill guards, forward
and backward overlap, fuel preservation, frame wrap, immediate and actual
EVENT_WAIT, consumed/stale completion rejection, actual owned-seed
replacement, multiple WAIT_REU wakes and cancellation of their live driver.
The final cancellation regression creates a real pending code fetch: the
uncorrected scheduler leaves its unrelated waiter stranded with an empty
runnable queue, while the corrected path enqueues it with unchanged fuel.
The [negative control and both corrected target records](m3-evidence/scheduler-cancel-regression.json)
preserve source/PRG hashes, the failing comparison and actual queue/fuel state.

The autonomous suite runs three four-process packs. Two cold non-yield loops
continue while 2051-byte fill/copy jobs rotate and complete; the entire output
and end guards must match. A second pack checks positive sleep, wake-to-first
dispatch latency and fault isolation. A third observes an already-progressing
pending 30000-byte job, cancels it through the actual native cleanup request,
and verifies other owners complete. Every pack checks all 64000 source pixels
and both output rows, missed syncs, DMA exclusion and an idle margin record.
The fair-job pack also pauses the scheduler for 50 ms at a coherent boundary,
programs a real CIA2 one-shot through the documented monitor I/O lens, and
requires NMI/recovery counter advances while every guest context and cache
buffer, tag and continuation stays byte-identical. Native SP and kernel code
are preserved. It resumes the ordinary scheduler and requires both jobs and
live scanout to finish. Raw-RAM monitor writes are never counted as CIA edges.
Its JSON includes target frames, native timing, DMA bytes, owner switches,
completion counts, stack sentinel, build hashes and complete diagnostic state.
Private backend/REU copies are reused between scenarios. These are bounded
functional and latency tests, not host-controlled VM stepping.

The final cumulative suites passed all three four-process packs for each cache
profile, using the normal 260–299 admission interval. Their fair-job results are:

| Cache line | Fair-job loop retirements | Simultaneous native phase deltas | Maximum measured native work interval | Observed stack lower bound |
| --- | --- | --- | --- | --- |
| 64 bytes | 30,715 / 30,699 | 78 / 76 | 76 PHI2 | 16 bytes |
| 128 bytes | 35,357 / 35,340 | 79 / 77 | 139 PHI2 | 16 bytes |

The phase deltas come from one coarse 400 ms observation while both owners
were pending; reads are sequential rather than atomic phase barriers. Each
fill completed 684 successful phases and each copy 1368. Both profiles observed
one actual CIA2 NMI/recovery, retained identical paused VM/cache state and
matched the full raster pattern. All six pack captures had zero missed syncs
and active-pixel DMA, an idle unqualified margin record and a 16-byte observed
stack lower bound. The maximum measured native work interval across all packs
was 76 PHI2 for 64-byte lines and 140 PHI2 for 128-byte lines.

Both sleep fixtures observed six frames including timestamp instructions and
zero frames from wake to first dispatch. The progressing 30000-byte fill was
cancelled after 120 bytes/40 chunks with 64-byte lines and 117 bytes/39 chunks
with 128-byte lines; the unrelated 2051-byte copy completed in both cases.
These bounded observations do not claim an upper bound under arbitrary
interference or physical timing qualification.
