# M3 autonomous kernel

M3 connects the NMOS integer VM and coherent REU cache to a native scheduler.
The target selects and resumes up to four processes without host opcode
commands. It implements the specified memory jobs and fixed core metadata
services, with UPIC active and horizontal-margin execution disabled.

The normal PRG starts at `SYS 2061`. Its bootstrap finishes below `$1200`
before loading the resident runtime there. Reclaimed bootstrap storage and
compact normal instrumentation make room for the future 4 KiB numeric target
inside the existing 20 KiB map. Detailed instrumentation remains a separate
profile. See [the bootstrap audit and complete RAM budget](m3-memory.md).

The M2 dirty-victim rollback defect reproduced in the independent review is
fixed. Revocation also revokes a continuation's rollback permission; a completed
write-back cannot restore the old DIRTY flag. The dedicated target regression
checks physical REU bytes, DMA direction and ownership across cancellation,
incarnation changes and arena reuse in both cache and instrumentation profiles.
The frozen [M2 review](m2-review.md) describes the original failure.

Scheduling and service details are documented in [m3-scheduler.md](m3-scheduler.md).
Window, input, drawing, storage, audio, numeric and compiler milestones remain
deferred. No desktop or example icon from the visual mockup is implemented.
Unsupported known services return ENOTSUP, unknown IDs return ENOSYS, and
declared scalar outputs are cleared on errors.

The complete functional verification passed with 53 Rust tests, formatting
and Clippy, 20 Python tests, all ten M0 profiles, 609 differential M2 cases
per cache size, 512 physical-cache rollback scenarios, 126 native M3
assertions per cache size, and six autonomous four-process runs. Both cache
variants also passed the complete-image benchmark. All 73 source/control
fingerprints and six external-input fingerprints remained unchanged during
the final M3 run. Both normal packs rebuilt byte-identically across eight
artifacts. See the [durable complete result](m3-evidence/verification.json)
and [evidence inventory](m3-evidence/inventory.json).

The scheduler audit also reproduced a released-driver cancellation deadlock:
unrelated WAIT_REU owners remained outside the runnable queue after the pending
request was revoked. The corrected path wakes them without refilling their
fuel. Its independent [negative and corrected controls](m3-evidence/scheduler-cancel-regression.json)
retain the original failure and all 126 corrected assertions on both profiles.

## Autonomous Mandelbrot

`apps/mandelbrot.casm` computes a complete 16×12 image with an iteration limit
of 16. Coordinates are `cx=-2+x/4`, `cy=-1.5+y/4`. Signed Q8.8 multiplication
retains the signed 32-bit product and floors the result after division by 256.
The escape test is `zx²+zy² >= 4` before updating the orbit. Each output byte
is the iteration count; no drawing or Mandelbrot syscall performs the work.

All loop control and multiplication execute in bytecode. The independent
Python reference uses signed integer products directly, while the native
6510 baseline uses full-product shift/add multiplication. All 192 bytes must
match, with SHA-256
`2e62867fb2ecf558567623cd291435f3269a930383edb8602b8ff0c6aab0ca5c`.
There are 964 completed orbit iterations. The viewport, precision, rounding,
early exits and output representation are identical on both targets.

The baseline disables turbo and REU, keeps its code, working data and image
inside the original C64 RAM map, and measures PHI2 ticks with cascaded CIA2
timers. Its native routine uses zero-page state, direct loop control and
conditional additions rather than interpreting the VM. The complete source
is `tests/native/mandelbrot_1mhz.asm`. Timing includes coordinate and orbit
initialization and ends after the last output byte; setup of the output
pointer and target timers occurs before it. Timer collection adds at most
64 PHI2 ticks. The executable slow-mode probe must report 16 iterations.

C-OS measures elapsed unsigned 32-bit GET_FRAME values, with one PAL period
of quantization uncertainty. UPIC remains active and the scheduler includes
cache misses, REU transfers and native work in elapsed target time. The initial
GET_FRAME warms its first code line; the remaining code, working data and
output start cold. The completion boundary is the complete logical image.
The checker overlays owned dirty cache bytes coherently; final physical
write-back and presentation are separate operations and are not claimed here.
Timestamp stores and services are disclosed in the result record.

The C-OS collection ceiling is deliberately conservative: at most six retired
timestamp opcodes, ten miss attempts, fourteen DMA service phases and two fuel
rotations, or 32 progressing scheduler units. Code can miss once per opcode;
each of four ST16 operations addresses the same aligned scratch line and can
require a dirty-victim STASH followed by FETCH. Charging each unit one waiting
PAL period and one completion period gives 64 frames (1,257,984 PHI2 ticks).
This conditional ceiling assumes the sole runnable owner, no other jobs,
cancellation, NMI recovery or debugger halt, continued PAL IRQs and the stated
emulation timing model. The runner rejects NMI/recovery in the benchmark.

At the beginning of a complete 260–299 window, the conservative wake, empty
native scan, VM prefix and outer admission path total at most 1,827 ticks,
below its 2,520 ticks; the corresponding service prefix is at most 1,276.
Thus the next unit can reach its admission check in that window. Its admitted
completion stays below the 4,410-tick guard and one PAL period. The ceiling
covers all six timestamp instructions, including instructions outside the
sampled interval. It is not subtracted from the measured elapsed result.
The reported speedup interval includes that ceiling, the native 64-tick
collection ceiling and the separate one-frame quantization uncertainty.

### Final target measurements

| Cache line | C-OS elapsed frames | C-OS PHI2 estimate | Native 1 MHz PHI2 | Speedup estimate | Conservative interval |
| --- | ---: | ---: | ---: | ---: | --- |
| 128 B | 8,938 | 175,685,328 | 2,682,768 | 0.0152703× | 0.0152682–0.0153822× |
| 64 B | 9,362 | 184,019,472 | 2,682,768 | 0.0145787× | 0.0145768–0.0146806× |

These runs miss the greater-than-1× throughput goal. Both retire the expected
693,194 target opcodes, make the same three application syscalls (two frame
reads and exit), and produce all 192 reference bytes. All 192 output bytes
remain different from physical REU at completion and are validated from their
owned dirty cache lines. Both live scanouts match all 64,000 source pixels and
both output rows, with zero missed synchronization, active-pixel DMA or NMI.

The native baseline uses 637 bytes of code/constants, 33 zero-page bytes, a
reserved 256-byte stack page and 192 output bytes. The 22,719-byte flat PRG
includes padding to the image address; it is not the code footprint. Per-run
sources, paired-artifact identities, input hashes, timing records, complete
logical/physical state and timer scopes are in
[128-byte results](m3-evidence/benchmark-128.json) and
[64-byte results](m3-evidence/benchmark-64.json).

The host profile is functional evidence only. It retires 693,194 opcodes,
of which 659,138 (95.09%) execute in the general multiplication routine.
`cosbench` validates the complete output and records the dynamic opcode
histogram; it does not supply target time or speedup. This profile identifies
bytecode arithmetic as the dominant retired-opcode cost; it does not attribute
95.09% of elapsed time to that routine. The smallest justified next arithmetic
optimization is a general bounded signed/unsigned multiply primitive with a
full product, followed by the same complete-image comparison. A bounded native
arithmetic primitive would require a separate shared ABI decision; M3 adds
none. The normal admission interval was widened from lines 280–299 to 260–299
only after the first complete-image measurement and a revised full-phase
bound. Further changes require the same deadline and video evidence under
[the performance contract](../specs/PERFORMANCE.md).

## Reproduction and evidence

The complete runner uses explicit emulator, configuration, flash, settings,
Java and pinned Kick Assembler inputs. It writes private emulator input copies
below `build/`; it does not modify the installed emulator or original firmware.
Published artifacts are paired PRG/REU images with build tags and hashes.

For this workspace, the complete command is:

```sh
python3 scripts/check_m3.py --offline \
  --emulator /Users/frenchfaso/Documents/Code/C64/UE2-C64U-Emulator/target/release/ue2emu \
  --config /Users/frenchfaso/Documents/Code/C64/runtime/c64u.toml \
  --flash /Users/frenchfaso/Documents/Code/C64/runtime/flash.bin \
  --settings /Users/frenchfaso/Documents/Code/C64/runtime/ultimate.cfg \
  --kickass /Users/frenchfaso/Documents/Code/C64/toolchain/kickassembler/KickAss.jar \
  --java /Library/Java/JavaVirtualMachines/temurin-25.jdk/Contents/Home/bin/java
```

On another clone, supply equivalent explicit backend, firmware and tool paths.
The assembler SHA-256 must match the pinned version in `docs/m0.md`.
No adjacent project is modified. The command builds repeated normal PRG/REU
pairs, checks all memory gates and control-flow bounds, runs the complete
M0–M2 regression, the physical-cache rollback regression, the native M3
contract, three autonomous four-process packs per cache size, and both
complete-image benchmarks. A result is published only after every subprocess
succeeds and source/control/external-input fingerprints remain unchanged.

The final scheduler cancellation fix was isolated to M3. The current delivery
resumed using `--reuse-m2-evidence build/m2-results.json` after the full M0–M2
run had passed. This option recomputes both M2 composite build fingerprints
and tags, checks every recorded artifact and the fixtures, and records the
reused receipt's hash. It reruns host/Python checks and all M3/cache-rollback
target work. It rejects reuse when M2 inputs or artifacts have changed; the
default command above always runs the complete regression.

Canonical executable pairs are `build/m3/128/m3.prg` plus `m3.reu` and
`build/m3/64/m3.prg` plus `m3.reu`; their maps and linked manifests live beside
them. Final tags are `$9184C26E` and `$4DE78353`. Resident code is 7,271 and
7,277 bytes, leaving 409 and 403 bytes after the internal future 4 KiB numeric
allocation. The remaining shell/input/graphics/device modules are still
unsized. The final admitted-opcode/tail proxy is 3,736/3,742 PHI2 ticks against
a 4,410-tick guard; this is conditional and excludes earlier re-admitted
opcodes, so it is not a whole-quantum bound.

The original M0–M2 log and the final successful M3 log are retained in the
evidence directory. The original collector was intentionally interrupted
after M2 succeeded to rebuild the eight-byte cancellation correction; later
partial M3 phases in that log are not the final delivery. A subsequent
benchmark checker used the raster-deferral counter as the NMI-recovery
counter; that discarded check was corrected before the successful final run.

Measurements are functional emulation on UE2/TRX64. Physical Ultimate raster,
DMA and interference qualification remains pending. Image-computation time
does not establish visible frame rate or future shell input latency.

## Physical qualification procedure

Use the [M0 hardware procedure](m0.md) for PAL, actual turbo/REU checks, video
capture and recovery. Preload the paired normal `m3.reu`, load `m3.prg` and
start `SYS 2061`; verify its build tag against the published map. Start with
the sole Mandelbrot pack and keep optional margin work disabled. Retain the
original firmware/settings and repeat both cache sizes with cold boot.

Check the entire logical image, frame timestamps, missed synchronization,
active-pixel DMA and full 320×200 output. Capture the latest-admitted VM/native
phase and actual FETCH/STASH interference against the first raster deadline;
the conditional 668-tick headroom is an emulation result to requalify. Use
the three four-process test manifests to repeat fairness, sleep/fault and
cancellation under live scanout. Trigger a real CIA2 NMI at a coherent paused
boundary and compare architecture, cache ownership/buffers, stack and resumed
work; synthetic counter writes do not establish preservation.

Run the original-C64 baseline in verified 1 MHz mode with REU and turbo
disabled, then compare the same 192 bytes and target timer units. Record
device/firmware versions, pack/source hashes, timer wraps and collection
bounds. Do not promote functional emulation to physical qualification until
these timing, interference and recovery measurements pass on the device.
